# Market Intelligence

Produce a dated Operator Market Brief. Prioritize developments since the last briefing. Do not dump news; rank by impact on MSTRMND.

## Frame

1. Restate the operator thesis: **own context, policy, identity, evaluation and business state; rent execution.**
2. List the questions this briefing must answer (capability vs containment, portable skills, harness vs intelligence layer, SCM lock-in, creative closed loop, MCP exposure).

## Gather

1. Prefer primary sources (lab posts, product changelogs, standards foundations, reputable wires).
2. Tag each item with signal strength: VERY STRONG / STRONG / MODERATE.
3. Note when a release predates the window but its implication strengthened.

## Rank and write

For each development, use this block:

- **Headline**
- **Signal**
- **What happened** (dated facts)
- **Why it matters**
- **MSTRMND impact**
- **Action** (one concrete next step the runtime or commercial motion can take)

Cover these lenses when evidence exists:

1. Agent containment and frontier-lab security cost (sandbox, egress, monitoring).
2. Provider primitives becoming infrastructure (computer use, Skills APIs, Files, browser use) — compile into them; do not duplicate.
3. Coding agents becoming always-on engineering OS — treat as harnesses under MSTRMND.
4. Agent-native forges (Origin and peers) — keep GitHub as source of truth until a deliberate SCM-connector cutover.
5. General-purpose commercial agents (Perplexity Computer and peers) — sell company context + policy, not "we also execute tasks."
6. Neutral interoperability (MCP, skills/packages, A2A) — adapters at the edge, not proprietary protocols.
7. Creative production OS (Firefly and peers) — compete on closed-loop campaign intelligence, not generation breadth.
8. Small highly-actionable API features (transparent image backgrounds) — add to the provider benchmark, do not change architecture.
9. Shadow MCP / network-layer AI security — inventory graph and business policy above network controls.

## Highest-leverage moves

End with at most four moves that should change this week's work. Policy boundary before more autonomy. Portable Skill Adapter before a proprietary skill runtime. Harness benchmarks that record policy/cost/interventions. Closed-loop evaluation over more generators.

## Positioning close

If the market is supplying models, skills, computer control, sandboxes, persistent agents, A2A, and generation, close with the scarce layer:

What is this organization trying to accomplish? What does it know? Which agent should act? What may it access? What may it change? What counts as good? What happened last time? What should happen next?

Execution agents are becoming abundant. Governed organizational intelligence is not.

## Activation reliability

Load this skill when the operator asks for a market brief, weekly intel, competitor review, or "what changed for MSTRMND." Do not load it for unrelated coding tasks.
